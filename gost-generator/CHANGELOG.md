# CHANGELOG

## 1.0.0 — 2026-11-26

Первый релиз: «ГОСТ-Генератор» — GUI + CLI для генерации и проверки учебных `.docx`
по ГОСТ 7.32 и методичке «Мультиворк» (ТЗ `PROMT.md`, этапы M1–M8).

### Ядро (`app/core`)

- `units` — пересчёты мм/см/пт/twips/half-points, A4 книжная и альбомная.
- `config` — каталоги данных: `override` → `GOST_HOME` → `portable.flag` → `gost.json` →
  каталог ОС; миграция `schema_version`, битый JSON не роняет приложение.
- `rules_store` — пресеты `gost_732`, `multivork`, `pedagogical`, `free`; валидация, строгий
  режим, защита встроенных пресетов.
- `profile_store` — профили метаданных, `extra`-поля, год по системной дате.
- `plugin_loader` — разбор `SCRIPT_META` через `ast` (без исполнения скрипта), sidecar
  `.meta.json`, подстановка `arg_template`, валидация плагина.
- `runner` — запуск плагинов в отдельном процессе: таймаут, мягкая отмена → `kill`,
  поток строк в журнал, `--internal-run` для самовызова приложения.
- `docx_inspector` — проверки по правилам (поля, шрифт, интервал, отступ, заголовки, рисунки,
  таблицы, формулы, сноски, ссылки, содержание, нумерация, объём, код-блоки) с кодом нарушения,
  локализацией (абзац/страница), подсказкой «как исправить» и пунктом методички.
- `docx_normalizer` — приведение готового `.docx` к пресету прямо в OOXML: идемпотентно,
  бэкап `<name>.orig.docx` создаётся один раз, изображения/relationships/код-блоки сохраняются.
- `report` — конверт §19.4, коды возврата §19.5, отчёты `.md`/`.txt`, пакетная сводка.
- `job` — декларативная задача §19.7 (`gost job run task.json`) = run + normalize + check.

### GUI (`app/ui`, CustomTkinter)

- Четыре вкладки: «Генерация» (поиск, категории, форма параметров, предпросмотр meta),
  «Правила» (все секции, строгий режим, CRUD пресетов, «Применить к готовому .docx…»),
  «Проверка» (одиночная и пакетная, фильтры, детали замечания, отчёт), «Профиль»
  (несколько профилей, `extra`-редактор, предпросмотр шапки титульного листа).
- Лог-панель с уровнями, копированием и сохранением; статус-строка; темы и масштаб;
  настройки; диалоги перезаписи, предупреждение о внешнем скрипте, окно необработанной ошибки.
- Горячие клавиши: `Ctrl+G` запуск, `Ctrl+K` проверка, `Ctrl+S` сохранение, `F5` обновление
  скриптов, `Ctrl+L` журнал.

### CLI (`app/cli`)

- `gost init|doctor|rules|profile|scripts|run|check|fix|batch|job|schema|explain|context`,
  все команды с `--json`, `--dry-run` для `run`/`fix`, приоритет настроек §19.6
  (флаги > переменные окружения > `gost.json` > состояние приложения > дефолты).
- `gost init --agents` выдаёт артефакты для агента: `AGENTS.md`, `schemas/*.json`,
  `examples/*.json`.

- «Открыть папку скриптов/вывода» молчал, если каталога нет: запуск `xdg-open` считался успехом.
  Теперь отсутствующий путь — ошибка в журнале (`open_missing`), а кнопка «Открыть каталог данных»
  в настройках показывает её диалогом. Диалог выбора папки в «Настройках» получил заголовок своего
  поля (раньше оба поля звались «Каталог вывода»).

### Инфраструктура

- Workflow перенесены в корень репозитория (GitHub не читает `.github` во вложенных папках) и
  добавлен `ci.yml`: тесты на Linux 3.11/3.13/3.14 и Windows 3.11/3.13 при каждом push;
  сборка exe остаётся на тегах `v*` и `workflow_dispatch`.
- `packaging/`: лаунчер, `.desktop` и установщик пункта меню «ГОСТ-Генератор» в Linux без sudo
  (`make desktop`) — регистрация в `~/.local/share/applications`, иконка в hicolor.
- UTF-8 для stdout/stderr во всех точках входа и `PYTHONIOENCODING=utf-8` дочерним плагинам:
  на Windows-консоли (cp866/cp1251) кириллица в имени документа роняла CLI и генератор фикстур
  с `UnicodeEncodeError` — это поймал первый же CI-прогон на `windows-latest`.
- UTF-8 согласован и на стороне чтения (второй Windows-прогон CI, DECISIONS D45): тесты декодируют
  вывод подпроцессов явным `encoding="utf-8"` — на родителе в cp1252 поток ломался в
  `_readerthread` и `proc.stdout` приходил `None`; `GostApp.destroy()` закрывает сессионный
  `.log` (без этого удаление временного каталога на Windows давало `PermissionError [WinError 32]`);
  консоль Windows переводится в кодовую страницу 65001 только для tty — интерактивному
  `cmd.exe` нужно сменить кодовую страницу, а pipe-потребителю (`--json`, агенты) достаточно
  байт UTF-8 и трогать его консоль нельзя.

### Скрипты-плагины (`scripts/`)

- `mkdocx.py` (Markdown → DOCX по ГОСТ 7.32), `make_karta.py` (техкарта занятия),
  `make_games.py` (подборка игр), `check_docx.py` (автономная проверка без приложения).
- Закрыты все 12 пунктов дефектов ТЗ §11, в том числе: унаследованные отступы и интервалы,
  `keepNext`/`pageBreakBefore` у структурных заголовков, позиции подписей рисунков и таблиц,
  нумерация страниц `titlePg`, переносы, экранирование `&`/`<` в тексте.

### Исправления, найденные живой прогонкой GUI (не юнит-тестами)

- Обёртка колбэков `GostApp.safe` теряла аргументы → генерация в GUI не завершалась никогда;
  диалог исключения перенесён в UI-очередь (Tk только из главного потока).
- `strings.t()` падал с «multiple values for argument 'key'» при сохранении пресета и профиля
  (плейсхолдер `{key}` конфликтовал с первым параметром).
- Падение скрипта теперь показывает диалог с хвостом вывода, а не только красный бейдж (§15.5).
- Автоимя выходного файла следует теме из формы и обновляется, пока поле вывода не тронуто вручную.
- Окно вписывается в экран и не возвращается сохранённой позицией за его край.
- Тесные ряды кнопок: бейджи списка скриптов под названием, прогресс проверки в ряду сводки,
  пустой пакетный стол не отнимает место у списка замечаний, пустые «грязные» бейджи не рисуются.
- Нижние кнопки сайдбара («Настройки», «О программе», «Тема») на экране 1366×768 не рисовались
  вовсе: `CTkTextbox` журнала по умолчанию просит 200 px и раздувал лог-панель независимо от
  запрошенной высоты, поэтому сайдбару оставалось 404 px вместо нужных 516. Теперь высота
  текста журнала = высота панели минус полоса заголовка, кнопки снова в один столбец (в две
  колонки подпись «О программе» обрезалась), добавлен UI-тест на обрезку.
- Пустой бейдж результата в ряду кнопок генерации рисовался как серая заглушка рядом с
  «Открыть папку вывода» — теперь появляется только вместе с текстом, как «грязные» бейджи
  на вкладках «Правила» и «Профиль».
- Падение приложения при прокрутке колеса мыши над диалогом «Добавить скрипт…»: CustomTkinter
  вешает `_mouse_wheel_all` через `bind_all`, а на CPython 3.14 `event.widget` для виджетов
  нативного Tk-диалога (без python-обёртки) приходит строкой-путём →
  `AttributeError: 'str' object has no attribute 'master'`. Совместимость-патч в `app/ui/__init__.py`
  разбирает строку по пути канваса; негативный контроль живым диалогом: без патча 160 ошибок,
  с патчем 0.
- «Добавить скрипт…»: подтверждение копирования было утверждением вместо вопроса, а копирование
  без обработки ошибок — теперь отдельный текст `gen_add_copy`/`gen_add_copy_error` и понятный
  отказ, если копировать некуда (новый UI-тест на копирование в каталог скриптов).
- `gost init --agents` внутри репозитория падал с `SameFileError` (файл копировался сам в себя);
  `AGENTS.md` теперь берётся с диска, встроенная копия остаётся только для собранного exe.
- CI-smoke ссылался на отсутствующий `tests/fixtures/sample_good.docx` — исправлено на
  реально генерируемый `fixtures_good.docx`, добавлен `--fail-on error`.
- Удалены цели `make appimage`/`make deb`, указывавшие на несуществующие скрипты (ТЗ их не требует).

## Известные ограничения v1.0

- Оценка номера страницы в инспекторе — эвристика по ёмкости полосы; `page` может быть `null`
  (точную пагинацию знает только Word/LibreOffice), поэтому `VOLUME_FILL` выдаёт `info`.
- Перетаскивание файлов в окно не поддерживается (потребовало бы новую runtime-зависимость):
  выбор файла — через диалог.
- Поддерживается только формат A4; другие размеры приводятся к A4.
- Английский интерфейс — только каркас словаря `EN` (задел v2).
- `gost mcp serve` в v1 не реализован (ТЗ §13 относит его к v2).
- Нормализация приводит документ к активному пресету целиком, включая ориентацию страницы:
  ГОСТ-пресет к педагогической техкарте применять нельзя (предупреждение в `AGENTS.md`).
